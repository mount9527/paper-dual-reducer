# dsh-paper-dual AIGC 分数可信度提升建议

**对象**：dsh-paper-dual 插件「AIGC 考官」模块
**缘起**：同一篇论文（《推荐算法在物流领域应用中的问题分析_第5题》），插件报 32.0%，笔灵 paper-ai-detect 报 7.1%，相差 4.5 倍
**日期**：2026-11-17
**结论**：不是缺陷，是口径、粒度、模型刻度三处系统性错位；其中三分之二可在一到两天内修掉

---

## 一、结论摘要

1. 32.0% 与 7.1% 不是同一个量。前者是 472 段概率的字数加权均值，后者是「被判疑似 AI 的片段字数 ÷ 总字数」。两者不可直接比较，也不该互相验证。
2. 拆开看，差距可以量化归因：口径转换解释 7.3 个百分点，切分粒度解释 5.0 个百分点，剩下 12.6 个百分点（2.8 倍）是模型本身。
3. 最要命的不是「偏低或偏高」，而是均值落在分布的空档里：66% 的字数在 0.3 以下，23% 在 0.8 以上，中间只有 11%，均值 0.32 落在几乎没有样本的位置。
4. 模型并非没有判别力。正文段分位数为 0.03 / 0.05 / 0.13 / 0.78 / 0.98，中位数 0.13，双峰清晰。是「求平均」这一步把信息毁了。
5. 可信度可以显著提高，但必须分层做：先口径（零成本），再切分（一天），再对齐引擎（唯一的真解），校准放最后。

---

## 二、实测事实

### 2.1 两份报告的正面对照

| 项目 | dsh-paper-dual（真机） | 笔灵 paper-ai-detect |
|---|---|---|
| 数值 | 32.0% | 7.1% |
| 语义 | 段落概率的字数加权均值 | 疑似 AI 片段字数占比 |
| 字数 | 16 264（含 471 个分隔换行） | 16 290 |
| 分段 | 472 段，平均 32 字/段 | 46 段，平均 354 字/段 |
| 分布 | 61 段 ≥0.5（3 790 字，24.7%） | 4 段标红，1 157 字 |
| 引擎 | yuchuantian/AIGC_detector_zhv3（单模型） | 报告标注「腾讯朱雀 AIGC 检测模型」，页面称模拟知网/维普/格子达 |
| 标签方向 | ai_index=1，标定 gap=0.3059，可信 | 人工 92.9% / 疑似 7.1% / AI 特征 0% |

### 2.2 文本同一性核对

同一份 docx，字数差 26。这不是文本差异：doc.json 正文 15 322 字，按 `\n\n` 拼接后为 15 322 + 471 × 2 = 16 264，与面板显示完全吻合；笔灵的 16 290 是它自己的统计口径。**文本不是变量，可以排除。**

### 2.3 三步归因（同一份逐段数据重算）

| 步骤 | 数值 | 变化原因 |
|---|---|---|
| 插件面板原值 | 32.0% | 472 段概率均值 |
| 换成平台口径 | 24.7% | 改为「≥0.5 的字数占比」 |
| 再换成平台粒度 | 19.7% | 472 段 → 39 个约 350 字片段，带上下文重打分 |
| 平台实际报告 | 7.1% | 换引擎 |

### 2.4 三个硬证据

**证据一：模型刻度未校准，人类基线在 0.65 附近。**
用插件自带样本实测：human_sample.txt 全文均值 0.6455（段均 0.7304）、ai_sample.txt 0.9997、标定探针 AI 组 0.9969 对 人写组 0.6910。也就是说这个模型给人写文本的基线分本来就在 0.6 上下，0.32 在它自己的刻度上属于偏低，但拿到朱雀的 7.1% 旁边就是两个尺度。

**证据二：切分边界一动，分数就跳 0.4。**
同一段文字单独打分 0.9945；并入包含它的 478 字片段后变成 0.5994。而笔灵对同一边界片段的判定是 0.6571——**同一粒度、同一文本下，两个引擎其实相当接近**。错位主要发生在汇总方式，不是模型完全对不上。

**证据三：短段是噪声源。**
472 段里 378 段不足 15 字（占 12.1% 字数），模型对这些碎片的输出没有任何语义基础：
标题「需求感知的物流服务推荐：」0.8789、「属性过滤与偏好重排相结合的改进方法」0.9823、「关键词：物流服务推荐；…」0.9898、「1 问题提出与场景界定」0.7322、「1.1 研究对象」0.2676，而同一篇正文段「本文讨论的场景…」只有 0.0227。平台把这些内容并成约 354 字的片段，标题与关键词的极端值被正文稀释。

## 三、「可信」应当怎么定义

「准不准」这个问题没有答案，因为 AIGC 检测没有真值，平台之间也不一致（同一篇在朱雀、知网、维普之间能差 20 个百分点）。工程上应该拆成三个可测的目标：

| 目标 | 现状 | 验收口径 |
|---|---|---|
| 稳定 | 不满足 | 同一篇用 3 种切分各跑一次，极差应 ≤5 个百分点 |
| 可解释 | 不满足 | 一句话能说清这个数是什么的占比 |
| 可对齐 | 不满足 | 与目标平台报告的 Spearman ≥0.8、判档一致率 ≥80% |

## 四、改进方案

### A 层：口径改造（半天，零依赖，收益最大）

**改什么**
1. 弃用均值，改为三档占比，分母只计正文可检测字数（排除参考文献、附录代码、表格单元、公式、图表标题）：
   - 疑似 AI：0.5 ≤ p < 0.85
   - 高风险：p ≥ 0.85
2. 增补中位数作为「典型段落值」。
3. 阈值按本模型分布定，不要照抄平台的 0.99。本文档最高分 0.9995，0.85 已是硬高分线。

**用现有数据立刻可得的数字**
- p ≥ 0.5：24.7%
- p ≥ 0.85：17.5%
- 0.5–0.85：7.2%
- 正文段中位数：0.13

**验收**：面板上的数字可以被一句话解释——「全文 24.7% 的字数被判定为疑似 AI，其中 17.5% 落在高风险区间」。

**风险**：占比比均值的方差略大，短文档（<2 000 字）需提示样本不足。

### B 层：切分改造（约 1 天，解决抖动）

**改什么**
1. 少于 40 字的段落不独立打分：并入相邻段，或直接排除出分母。
2. 固定约 350 字的块，与主流平台粒度对齐，块内保留上下文。
3. 三种切分（段级 / 350 字 / 500 字）各跑一次，取中位数作为最终分。

**预期效果**：同一文本的分值抖动从当前的 0.4 量级压到 0.05 量级；短段噪声不再进入分母。

**验收**：随机抽 10 段，在三种切分下的分数极差 ≤0.1；全文分三次跑的极差 ≤5 个百分点。

**代价**：推理成本约 3 倍。CPU 上整篇耗时需重新测量并写进 README。

### C 层：概率校准（需 30–50 篇标注语料）

**改什么**
1. 温度缩放或 isotonic 回归，把人类基线 0.65 压回 0.1 附近。
2. 阈值改为分位数：取「人写样本假阳率 5%」对应的那一点，而不是 0.5。

**前置条件**：至少 30 篇已确认人写的论文、30 篇已确认 AI 生成的论文，且需覆盖学术中文分布，不能用网文凑数。

**提醒**：校准只改刻度不改排序，对 A 层占比口径的收益小于 A、B。样本不足时强行拟合，产出的是幻觉而不是校准。

### D 层：对齐引擎（唯一能让数字"像平台"的路）

**方案一（推荐）：接朱雀 API**
腾讯云 EdgeOne Makers 提供 `@makers/zhuque-text`，每月 50 万 token 免费额度，输入 `text`、`is_merge`，输出 `softmax_confidence`、`ratio_confidence`、`labels_ratio`、`segment_labels`。笔灵报告标注的就是同一个引擎，属同源对齐。接入后可直接复用其分段与判档，插件只负责诊断与改写，分数交给平台。

**方案二：锚定集映射**
收集 20–50 篇已有平台报告的论文，用分位数映射把本模型分数映射到平台分数量纲。成本高于方案一，且只能逼近。

**验收**：与平台报告排序一致（Spearman ≥0.8），判档一致率 ≥80%。

### 四层对比

| 层级 | 工作量 | 依赖 | 预期收益 | 能否对齐 7.1% |
|---|---|---|---|---|
| A 口径 | 半天 | 无 | 32.0 → 24.7，语义可解释 | 否 |
| B 切分 | 1 天 | 无 | 24.7 → 19.7，抖动显著下降 | 否 |
| C 校准 | 3–5 天 | 60 篇标注 | 刻度可信，排序不变 | 否 |
| D 对齐 | 1–2 天 | 朱雀 API 或锚定集 | 量级接近平台 | 是 |

---

## 五、不建议做的四件事

1. **不要调阈值凑 7.1%。** 阈值能凑出一个数字，凑不出一个结论；换一篇文档立刻失效。
2. **不要在四个样本上做校准。** 4 个点拟合出的映射函数是过拟合的另一种写法。
3. **不要用插件分数对外承诺通过率。** README 已写明「不模拟任何平台」，这条边界应当保持。
4. **不要用均值做改写前后对比。** 均值会被切分变化污染；对比应当用同一口径的占比。

## 六、落地顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| 第一步 | A 层口径改造 + 面板文案从「AI 概率」改为「疑似占比（篇内口径）」 | 数字可被一句话解释 |
| 第二步 | B 层切分改造 + 抖动测试脚本 | 三次跑极差 ≤5 个百分点 |
| 第三步 | D 层接入朱雀 API，作为「外部口径」副栏 | 与平台判档一致率 ≥80% |
| 第四步 | C 层校准（待语料齐备） | 人写样本假阳率 ≤5% |
